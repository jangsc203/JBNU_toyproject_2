## 2. 프로젝트 배경

전남 특산 농수산물은 품목별로 가격 변동 양상이 다르고, 유통 관계자는 여러 품목의 현재 시세와 흐름을 빠르게 비교해야 한다. 하지만 가격 확인, 흐름 파악, 위험 판단, 근거 정리가 분리되어 있으면 업무 판단이 늦어지고 설명 가능한 근거를 만들기 어렵다.

본 프로젝트는 KAMIS 가격 데이터를 수집하여 Supabase에 저장하고, 규칙 기반 위험 점수와 AI 기반 근거 설명을 제공하여 유통 관계자가 품목별 시세와 수급 위험을 빠르게 파악하도록 돕는다.

## 3. 프로젝트 목표

1. 전남 특산 농수산물의 가격 데이터를 자동 또는 수동으로 수집하고 저장한다.
2. 전체 대시보드에서 품목별 현재 시세와 간단한 가격 흐름을 카드 형태로 제공한다.
3. 품목별 기간 가격 추이와 변화율을 조회할 수 있게 한다.
4. 규칙 기반 위험 점수와 등급, 계산 근거를 제공한다.
5. 과거 분석 문서를 Pinecone에 등록하여 의미 기반 검색을 지원한다.
6. 사용자가 자연어로 질문하면 Supabase 수치와 Pinecone 문서를 근거로 답변한다.
7. 데이터 수집, 위험 분석, 벡터 동기화의 성공/실패 상태를 추적한다.
8. 브라우저에 외부 API 비밀키가 노출되지 않도록 한다.

## 6. 사용자 문제

유통 관계자는 다음 문제를 해결해야 한다.

1. 여러 품목의 현재 시세를 빠르게 비교하기 어렵다.
2. 가격 변화가 일시적 변동인지 위험 신호인지 판단하기 어렵다.
3. 위험 판단의 계산 근거와 데이터 기간을 함께 확인하기 어렵다.
4. 가격 변화 원인이나 과거 유사 사례를 별도로 찾아야 한다.
5. 데이터 없음, 수집 실패, Mock 데이터 여부를 구분하기 어렵다.

## 7. 핵심 사용자 시나리오

1. 사용자가 서비스에 접속한다.
2. 전체 대시보드에서 품목별 현재 시세와 간단한 가격 흐름 카드를 확인한다.
3. 가격 변동률 또는 위험 등급이 높은 품목을 선택한다.
4. 선택 품목의 기간별 가격 추이와 주요 지표를 확인한다.
5. 위험 점수, 등급, 부분 점수, 계산 근거를 확인한다.
6. AI에게 가격 변화 원인 또는 과거 유사 사례를 질문한다.
7. AI 답변의 사용 기간, 근거 문서, 데이터 한계를 확인한다.
8. 답변에 대한 피드백을 남긴다.
9. 데이터가 없거나 작업이 실패한 경우 시스템 상태에서 원인을 확인한다.

## 12. 주요 워크플로

### 12.1 데이터 수집

Cron 또는 수동 실행 → Edge Function → KAMIS 호출 → 파싱/정규화/검증 → Supabase upsert → 작업 결과 기록

### 12.2 위험 분석

가격 데이터 조회 → 데이터 충분성 검사 → 지표 계산 → 위험 점수 및 등급 결정 → Supabase 저장

### 12.3 벡터 인덱싱

위험 결과 조회 → 검색용 문서 생성 → Gemini 임베딩 생성 → Pinecone upsert → 동기화 상태 기록

### 12.4 AI 질의응답

사용자 질문 → 질문 유형 판단 → Supabase 정형 조회 → Pinecone 의미 검색 → 근거 통합 → Gemini 답변 생성 → 대화 및 근거 저장

## 14. 성공 기준

1. 동일 가격 데이터를 다시 수집해도 중복 행이 증가하지 않는다.
2. 대시보드의 현재 가격과 Supabase 가격 데이터가 일치한다.
3. 가격 추이 그래프와 DB 수치가 일치한다.
4. 위험 점수와 부분 점수, 가중치를 확인할 수 있다.
5. 검색용 문서가 Pinecone에 등록된다.
6. AI 답변에서 데이터 기간과 근거 문서를 확인할 수 있다.
7. 실패한 작업을 구분하고 재처리할 수 있다.
8. 브라우저에 비밀키가 노출되지 않는다.
9. 모든 Must Have 요구사항이 테스트 결과와 연결된다.

## 17. 승인 요청 사항

다음 항목은 구현 단계로 넘어가기 전에 사용자의 확인이 필요하다.

1. 주요 사용자를 유통 관계자로 확정한다.
2. 첫 화면을 품목별 현재 시세와 간단한 가격 흐름 카드가 나열된 전체 대시보드로 확정한다.
3. Must Have 범위를 `FR-01`부터 `FR-11`까지로 확정한다.
4. Should Have 범위는 구현 시간에 따라 `FR-12`부터 `FR-15`까지 순차 적용한다.
5. 미래 가격 예측, 자동 거래, 결제, 모바일 네이티브 앱, 별도 백엔드 서버는 제외한다.

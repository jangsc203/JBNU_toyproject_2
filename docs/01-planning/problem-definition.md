# 문제 정의서

## 1. 문제 배경

전남 지역의 농수산물은 계절, 산지 작황, 기상, 명절 수요, 유통 물량, 외부 시장 상황에 따라 가격 변동이 발생한다. 유통 관계자는 여러 품목의 현재 시세와 최근 흐름을 빠르게 파악해야 하지만, 실제 업무에서는 품목별 가격 정보를 따로 확인하고 변화 이유를 별도로 해석해야 하는 경우가 많다.

이 프로젝트는 전남 특산 농수산물의 가격 데이터를 한곳에 모아 현재 시세, 간단한 가격 흐름, 변동률, 수급 위험 정보를 함께 제공하는 웹 애플리케이션을 목표로 한다.

## 2. 현재 사용자가 겪는 불편

주요 사용자인 유통 관계자는 다음과 같은 불편을 겪는다.

| 상황 | 불편 |
|---|---|
| 여러 품목의 시세 확인 | 품목별 현재 가격을 빠르게 비교하기 어렵다. |
| 최근 가격 흐름 확인 | 가격이 일시적으로 오른 것인지 지속적으로 변하는 것인지 판단하기 어렵다. |
| 수급 위험 판단 | 가격 변동률, 변동성, 데이터 부족 여부를 함께 보고 판단하기 어렵다. |
| 의사결정 근거 정리 | 거래처나 내부 의사결정에 설명할 수 있는 근거를 따로 정리해야 한다. |
| 데이터 오류 또는 공백 | 데이터가 없는 상황과 시스템 오류를 구분하기 어렵다. |

## 3. 문제의 원인

1. 품목별 가격 정보가 업무 판단에 맞게 한 화면에 정리되어 있지 않다.
2. 현재 가격과 최근 흐름, 위험도를 함께 보여주는 구조가 부족하다.
3. 가격 데이터의 출처, 기간, 갱신 시각, 데이터 한계를 한 번에 확인하기 어렵다.
4. 가격 변화 원인이나 과거 유사 사례를 확인하려면 별도 검색과 해석이 필요하다.
5. 데이터 수집 실패, 결측치, Mock 데이터 여부 같은 품질 정보를 사용자가 알기 어렵다.

## 4. 프로젝트가 제공할 가치

이 프로젝트는 유통 관계자가 여러 품목의 현재 시세와 가격 흐름을 빠르게 파악하고, 수급 위험이 높은 품목을 먼저 확인할 수 있게 돕는다.

핵심 가치는 다음과 같다.

| 가치 | 설명 |
|---|---|
| 빠른 현황 파악 | 전체 대시보드에서 품목별 현재 시세와 간단한 가격 흐름을 카드 형태로 확인한다. |
| 위험 우선순위 확인 | 변동률, 변동성, 데이터 품질을 바탕으로 위험 점수와 등급을 제공한다. |
| 근거 기반 해석 | 위험 점수의 계산 근거와 사용 데이터 기간을 함께 표시한다. |
| 자연어 질의응답 | 가격 변화 원인, 과거 유사 사례, 위험 해석을 AI에게 질문할 수 있다. |
| 신뢰 가능한 운영 | 수집, 분석, 벡터 동기화 작업의 성공/실패 상태를 기록한다. |

## 5. 예상 사용자

### 주요 사용자

| 사용자 | 설명 |
|---|---|
| 유통 관계자 | 여러 전남 특산 농수산물의 현재 시세와 최근 흐름을 확인하고, 거래 또는 수급 판단에 참고하려는 사용자 |

### 보조 사용자

| 사용자 | 설명 |
|---|---|
| 생산자 | 본인 품목의 시세 흐름과 위험도를 참고하려는 사용자 |
| 지역 행정 담당자 | 지역 특산품 가격 변동과 수급 위험을 모니터링하려는 사용자 |
| 시장 분석 담당자 | 가격 데이터와 위험 분석 결과를 보고서나 분석 업무에 활용하려는 사용자 |
| 교육 과정 수강생 | PRD, Supabase, Pinecone, RAG 기반 개발 흐름을 학습하려는 사용자 |

## 6. 해결 범위

이번 프로젝트에서 해결할 범위는 다음과 같다.

1. 전남 특산 농수산물 품목 목록을 관리한다.
2. KAMIS Open API 기반 가격 데이터를 수집한다.
3. 품목별 현재 시세와 최근 가격 흐름을 대시보드에 표시한다.
4. 품목별 기간 가격 추이와 변동 지표를 제공한다.
5. 규칙 기반 수급 위험 점수와 등급을 계산한다.
6. 위험 점수의 계산 근거와 데이터 한계를 표시한다.
7. 검색용 분석 문서를 생성하고 Pinecone에 인덱싱한다.
8. Supabase 수치와 Pinecone 검색 결과를 기반으로 AI 질의응답을 제공한다.
9. 데이터 수집, 위험 분석, 벡터 동기화 상태를 확인한다.
10. 사용자 대화와 피드백을 저장한다.

## 7. 제외 범위

이번 프로젝트에서 해결하지 않을 범위는 다음과 같다.

| 제외 항목 | 이유 |
|---|---|
| 미래 가격 예측 | 검증 가능한 실습 범위를 넘어선다. |
| 자동 거래 또는 매매 | 정보 제공 서비스의 목적과 다르다. |
| 결제 기능 | 핵심 가격 분석 기능과 직접 관련이 없다. |
| 모바일 네이티브 앱 | React 웹 애플리케이션 범위에 집중한다. |
| 운영 환경 배포 | 기본 실습 범위에서 제외한다. |
| 복잡한 조직별 권한 | 사용자별 대화/피드백 격리 수준으로 제한한다. |
| 별도 FastAPI 또는 Express 서버 | Supabase Edge Functions를 서버리스 처리 계층으로 사용한다. |

## 8. 초기 성공 기준

1. 전체 대시보드에서 품목별 현재 시세, 최근 흐름, 위험 등급을 확인할 수 있다.
2. 동일 품목과 동일 날짜의 가격 데이터가 중복 저장되지 않는다.
3. 품목별 기간 가격 추이와 주요 지표가 Supabase 데이터와 일치한다.
4. 위험 점수와 부분 점수, 계산 근거를 확인할 수 있다.
5. AI 답변에서 사용한 데이터 기간과 근거 문서를 확인할 수 있다.
6. 수집 실패와 데이터 없음 상태를 구분할 수 있다.
7. 브라우저에 KAMIS, Pinecone, Gemini 비밀키가 노출되지 않는다.
8. 모든 Must Have 요구사항이 구현물과 테스트에 연결된다.

# 사용자 시나리오 및 사용자 흐름

## 1. 첫 화면 원칙

사용자가 서비스에 접속하면 가장 먼저 전체 대시보드가 보인다.

대시보드는 각 품목의 현재 시세와 간단한 가격 흐름이 담긴 박스형 카드 목록으로 구성한다. 유통 관계자가 여러 품목을 빠르게 훑어보고, 위험도가 높은 품목이나 가격 변동이 큰 품목을 바로 선택할 수 있게 하는 것이 목적이다.

## 2. 화면 후보

| 화면 | 경로 | 목적 |
|---|---|---|
| 전체 대시보드 | `/` | 품목별 현재 시세, 최근 흐름, 위험 등급을 한눈에 확인 |
| 가격 추이 | `/prices` | 선택 품목의 기간별 가격 흐름과 주요 지표 확인 |
| 위험 분석 | `/risks` | 위험 점수, 등급, 부분 점수, 계산 근거 확인 |
| AI 보고서 | `/reports` | 품목별 또는 종합 AI 분석 보고서 생성/조회 |
| AI 질의응답 | `/chat` | 가격과 위험 정보에 대한 자연어 질문 |
| 시스템 상태 | `/system-status` | 수집, 분석, 벡터 동기화 작업 상태 확인 |

## 3. 시나리오 1: 최신 가격 확인

| 단계 | 사용자 행동 | 시스템 처리 | 사용자에게 보이는 결과 |
|---|---|---|---|
| 1 | 서비스에 접속한다. | 최신 품목별 가격과 위험 요약을 조회한다. | 전체 대시보드가 표시된다. |
| 2 | 품목 카드 목록을 훑어본다. | 품목별 현재 시세, 단위, 변화율, 간단한 추세, 위험 등급을 표시한다. | 여러 품목의 현재 상태를 비교한다. |
| 3 | 변동률이 큰 품목을 확인한다. | 해당 품목의 카드에 상승/하락/변동성 표시를 제공한다. | 우선 확인할 품목을 고른다. |
| 4 | 품목 카드를 선택한다. | 품목 상세 또는 가격 추이 화면으로 이동한다. | 선택 품목의 상세 흐름을 확인한다. |

종료점: 사용자는 관심 품목의 현재 시세와 최근 흐름을 파악한다.

## 4. 시나리오 2: 특정 품목의 가격 추이 확인

| 단계 | 사용자 행동 | 시스템 처리 | 사용자에게 보이는 결과 |
|---|---|---|---|
| 1 | 대시보드에서 품목을 선택한다. | 선택 품목 ID를 기준으로 가격 데이터를 조회한다. | 가격 추이 화면이 열린다. |
| 2 | 분석 기간을 선택한다. | 기간 조건을 검증하고 Supabase에서 가격 이력을 조회한다. | 가격 선 그래프와 기간 요약 지표가 표시된다. |
| 3 | 평균, 최고가, 최저가, 변화율을 확인한다. | 조회 결과로 지표를 계산하거나 저장된 지표를 가져온다. | 숫자 지표와 그래프가 함께 표시된다. |
| 4 | 결측 구간이나 데이터 한계를 확인한다. | 데이터 품질 정보를 함께 조회한다. | 데이터 없음, 결측, Mock 여부가 표시된다. |

종료점: 사용자는 선택 품목의 기간별 가격 흐름을 확인한다.

## 5. 시나리오 3: 위험 점수와 계산 근거 확인

| 단계 | 사용자 행동 | 시스템 처리 | 사용자에게 보이는 결과 |
|---|---|---|---|
| 1 | 위험 등급이 높은 품목을 선택한다. | 해당 품목의 최신 위험 분석 결과를 조회한다. | 위험 분석 화면이 열린다. |
| 2 | 위험 점수와 등급을 확인한다. | 최종 점수, 등급, 분석 기간을 표시한다. | 높음/주의/안정 등 위험 상태를 본다. |
| 3 | 계산 근거를 펼쳐본다. | 부분 점수, 가중치, 사용 지표를 표시한다. | 변화율, 변동성, 데이터 수 등의 근거를 확인한다. |
| 4 | 계산 불가 항목을 확인한다. | 데이터 부족 또는 결측 사유를 표시한다. | 0점과 계산 불가가 구분되어 보인다. |

종료점: 사용자는 위험 등급이 나온 이유를 설명할 수 있다.

## 6. 시나리오 4: AI에게 가격과 위험 질문

| 단계 | 사용자 행동 | 시스템 처리 | 사용자에게 보이는 결과 |
|---|---|---|---|
| 1 | AI 질의응답 화면에서 질문을 입력한다. | 질문 유효성을 검증한다. | 처리 중 상태가 표시된다. |
| 2 | 예: "이번 주 김 가격이 왜 오른 것 같아?" | 품목과 기간, 질문 의도를 추출한다. | 검색/분석 중 상태가 표시된다. |
| 3 | 시스템이 Supabase와 Pinecone을 조회한다. | 정확한 수치는 Supabase에서 조회하고, 과거 문서는 Pinecone에서 검색한다. | 답변 생성 중 상태가 표시된다. |
| 4 | Gemini가 근거 기반 답변을 생성한다. | 수치, 검색 근거, 데이터 한계를 포함해 답변을 구성한다. | 핵심 답변, 사용 기간, 근거 문서가 표시된다. |
| 5 | 사용자가 피드백을 남긴다. | 사용자 피드백을 저장한다. | 피드백 저장 완료 상태가 표시된다. |

종료점: 사용자는 AI 답변과 근거를 확인하고 피드백을 남긴다.

## 7. 시나리오 5: 데이터 수집 실패 확인

| 단계 | 사용자 행동 | 시스템 처리 | 사용자에게 보이는 결과 |
|---|---|---|---|
| 1 | 대시보드에서 일부 품목의 데이터가 비어 있음을 확인한다. | 최신 수집 작업 상태를 조회한다. | 해당 품목 카드에 데이터 없음 또는 수집 실패 상태가 표시된다. |
| 2 | 시스템 상태 화면으로 이동한다. | 수집, 분석, 벡터 동기화 작업 이력을 조회한다. | 실패한 단계와 실패 사유 요약이 표시된다. |
| 3 | 실패한 품목만 재처리한다. | 재처리 가능한 작업인지 확인하고 Edge Function을 실행한다. | 재처리 요청 상태가 표시된다. |
| 4 | 결과를 다시 확인한다. | 최신 작업 상태와 가격 데이터를 다시 조회한다. | 성공 또는 재실패 상태가 표시된다. |

종료점: 사용자는 전체 장애와 일부 품목 실패를 구분하고 재처리 상태를 확인한다.

## 8. 빈 데이터 및 오류 흐름

| 상황 | 시스템 처리 | 사용자에게 보이는 결과 | 다음 행동 |
|---|---|---|---|
| 해당 기간 가격 데이터 없음 | 정상 빈 결과로 처리 | "선택한 기간에 가격 데이터가 없습니다." | 기간 변경 또는 다른 품목 선택 |
| 가격 값이 0 | 실제 0 값으로 표시하되 데이터 검증 상태 표시 | 0과 데이터 없음이 구분됨 | 출처와 검증 상태 확인 |
| KAMIS 인증 실패 | 작업 실패로 기록 | 수집 실패 상태와 관리자 확인 필요 표시 | 시스템 상태 확인 |
| Pinecone 검색 근거 없음 | 근거 부족 상태로 처리 | "관련 근거 문서가 부족합니다." | 기간 또는 질문 재입력 |
| Gemini 답변 실패 | 대화 오류로 저장 | 다시 질문 버튼과 오류 안내 표시 | 재시도 |
